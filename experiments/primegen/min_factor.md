# Algorithm C — the min-factor exponent-spine generator

**Status:** normative specification + analysis of a third construction. **Companions:** `paper.md` (primary
specification, §4C summarises this document), `algorithm.md` (§4C: pseudocode, §6: executable reference),
`generator.md` (architecture), `observation.md` (multiplier sets), `idea.md` (spectral reading), `fractal.md`
(lattice reading), `theory.md` (statement inventory).

---

## 0. Where this came from, and what survives of it

The original note observed that a sieve channel need not be described by a _coprime mask_. It can be described by
_min-factor geometry_: the numbers owned by `n` are

```
C(n) = ⋃_{a ≥ 1} n^a · { multipliers that introduce no prime smaller than n }
```

and asked whether that removes the need for explicit coprime sequences.

Two corrections before anything else, because the informal statement is easy to over-read.

1. **The multiplier cloud is a monoid, not an interval.** The note's `{1, …, P_{>n}}` is not a range of integers; it
   is the _multiplicative monoid generated by the primes `> n`_. Written properly (§1) it is `B_n`, and it is
   infinite. Nothing is bounded by a primorial here.
2. **The coprime condition is not removed; it is re-encoded.** `r ∈ B_p` _is_ the statement `gcd(r, P_{≤p}) = 1`.
   The reframing relocates the cost, exactly as the note itself concluded. Conjecture X1 (`paper.md` §2.4,
   `algorithm.md` Remark 2.9) applies verbatim, with `P_{≤p}` in place of `P_{<p}` (Remark M-X below).

What genuinely survives, and what this document specifies, is this:

- The exponent decomposition is a **strict refinement of the ownership partition** (Claim M1), so it is available for
  free — it costs no new mathematics, only a new index.
- Under the wheel relaxation of Algorithm B, that refinement **shrinks the claimant set of every composite**
  (Claim M10) and gives, for each rejected candidate, the triple `(spf(m), v_p(m), m/p^{v_p})` instead of a bare
  rejection (§8). Algorithm C is therefore a _streaming min-factor oracle_ that happens to emit primes as its
  unclaimed residue, rather than a prime generator that happens to know something about factors.
- The cost of that is measurable and small: touches equal to Algorithm B's within `Θ(N^{2/3}/log N)` (§7.1), memory
  `(1+o(1))·π(√N)` records in the thinned form (§7.3), one extra word of state per record, and `O(1)` random-access
  restart preserved (§7.4).

What it is **not**: it is not faster than Algorithm B, it is not exact, and it does not escape X1. The honest summary
is in §10.

## 1. Notation

Everything below is in the vocabulary of `paper.md` §2 and `algorithm.md` §1. Additionally:

| symbol                                         | meaning                                                        |
| ---------------------------------------------- | -------------------------------------------------------------- |
| `v_p(n)`                                       | `p`-adic valuation: largest `e` with `p^e ∣ n`                 |
| `B_p = { r ≥ 1 : q prime, q ∣ r ⟹ q > p }`     | the monoid generated by the primes `> p`; `B_p = {1} ⊎ R_{>p}` |
| `R_{>p} = { r > 1 : spf(r) > p }`              | the strictly-`p`-rough integers `> 1`                          |
| `P_{≤p} = ∏_{q ≤ p} q`                         | primorial through `p` (so `B_p = { r : gcd(r, P_{≤p}) = 1 }`)  |
| layer `(p, e)`                                 | the stream `p^e · B_p`                                         |
| `B̃_p = {1} ∪ { r ≥ p : gcd(r, W) = 1, p ∤ r }` | the **wheeled relaxation** of `B_p` used by Algorithm C (§5)   |
| `r₁(p)`                                        | least element of `B̃_p` greater than `1`, i.e. least admissible |

Note `B_p ⊆ A_p ∪ {1}` and `B_p ⊆ B̃_p`, with `B̃_p` decidable from a table of size `W` plus one divisibility skip.

## 2. Structure: the min-factor normal form

### 2.1 The refinement

> **Claim M1 (min-factor normal form).** Every integer `n > 1` factors **uniquely** as
>
> ```
> n = p^e · r ,   p prime,  e ≥ 1,  r ∈ B_p ,
> ```
>
> and then necessarily `p = spf(n)`, `e = v_p(n)`, `r = n / p^e`. Consequently
>
> ```
> ℕ_{>1} = ⨄_p ⨄_{e ≥ 1} p^e · B_p ,
> A_p    = (B_p \ {1}) ⊎ ⨄_{e ≥ 1} p^e · B_p ,
> Θ_p    = ( ⨄_{e ≥ 1} p^e · B_p ) \ {p} .
> ```
>
> _Proof._ Existence: take `p = spf(n)`, `e = v_p(n)`, `r = n/p^e`; then `p ∤ r` and every prime factor of `r`
> divides `n`, hence is `≥ p`, hence `> p`. Uniqueness: in any such factorisation `p` divides `n` and every other
> prime factor of `n` is `> p`, so `p = spf(n)`; and `p ∤ r` forces `e = v_p(n)`. The three displayed identities are
> that statement sorted by `p`, by `p` with the `e = 0` term separated (`A_p = Θ_p / p`), and by `p` with the single
> non-composite element `p = p^1·1` removed. ∎
>
> _Status: unique factorisation, re-bracketed. Not yet formalised; see §11._

Claim M1 is the precise form of the note's `C(n) = ⋃_{a≥1} n^a · {…}`. It is a **refinement** of Claim O1
(`paper.md` §2.2), not a competitor to it: summing the layers of `p` re-assembles `p·A_p = Θ_p`. Nothing about the
partition changes; only the index does — from "prime" to "prime and multiplicity".

### 2.2 Delegation: coprime sets as an emergent property

> **Claim M2 (cone recursion).** For every prime `p`,
>
> ```
> B_p = {1} ⊎ ⨄_{q > p prime} q · B_q .
> ```
>
> _Proof._ Immediate from M1 applied to `r ∈ B_p \ {1}`: its smallest prime factor `q` satisfies `q > p`, and
> `r / q^{v_q(r)} ∈ B_q`, so `r ∈ q·B_q`; conversely `q·B_q ⊆ B_p` for `q > p`. Disjointness is uniqueness of
> `spf`. ∎ _Status: routine; not formalised._
> **Correction M2′ (forced by the formalisation).** The displayed identity is **false as written**, and the proof
> sketch shows why: `r / q^{v_q(r)} ∈ B_q` gives `r ∈ q^{v_q(r)}·B_q`, which is `r ∈ q·B_q` only when
> `v_q(r) = 1`. Least witness: `9 ∈ B_2`, `spf(9) = 3 > 2`, but `9 = 3·3` and `3 ∉ B_3`, so `9` lies in no
> `q·B_q` (`MinFac.not_one_step_cone`). Two repairs, both machine-checked in
> `lean/Primegen/MinFactor.lean`:
>
> ```
> B_p = {1} ⊎ ⨄_{q > p} ⨄_{e ≥ 1} q^e · B_q          (run-length form; MinFac.cone_recursion)
> B_p = {1} ⊎ ⨄_{q > p} q · { s ≥ 1 : spf(s) ≥ q }   (one-step form; MinFac.exists_unique_cone_split)
> ```
>
> The run-length form is the one Algorithm C implements — it _is_ the layer index — and the one-step form is the
> one that keeps the disjointness (`q` is forced to be `spf(r)` in both). Nothing downstream changes: §9's
> graph-directed reading needs edges `p → q` with loops, which is exactly the run-length form, and the loops are
> precisely what the `e`-index encodes.

This is the content the note was reaching for. The multiplier cloud of `p` is **generated by the clouds of the larger
primes**; no residue system mod `P_{≤p}` is ever constructed. Coprimality is a _consequence_ of where you entered the
tree, not a precondition tested on the way in. Formally: the composites are the image of the regular language of
non-decreasing prime words `q_1 ≤ q_2 ≤ …`, Claim M1 is its run-length encoding at the head, and Claim M2 is its
one-step unfolding.

### 2.3 Phase separation, strict form

> **Claim M3.** If `r ∈ B_p` and `1 < r < (p+1)²` then `r` is prime (and `r > p`).
>
> _Proof._ Every prime factor of `r` is `> p`, i.e. `≥ p+1`; a composite `r` has at least two, so `r ≥ (p+1)²`. ∎
> _Status: same argument as `Primegen.prime_of_rough_of_lt_sq`, one step stricter; not separately formalised._

Consequences, layer by layer:

- Layer `(p, e)` advances by **index increment into the prime array** while its multiplier is `< p²` — no
  arithmetic, no wheel, exactly as in `algorithm.md` Lemma 2.7.
- A **composite** multiplier in layer `(p,e)` forces the emitted value `≥ p^{e+2}`. So layer `e` has a rough phase
  below `N` only for `p ≤ N^{1/(e+2)}`. For `e = 1` this is the familiar `p ≤ N^{1/3}`; for `e = 2` it is
  `p ≤ N^{1/4}`; the tower thins fast.
- The pure-power part of a layer (`r = 1`) is the **spine** `p, p², p³, …`, which is trivially generated.

### 2.4 Causality

> **Claim M4 (causality).** Let `m = p^e·r` be a value of layer `(p,e)` with `r > 1`, and let `r'` be the next
> element of `B_p` (or of `B̃_p`) after `r`. Then `r ≤ m/p ≤ m/2` and `r' < m`; `r'` is determined by the
> multiplicative structure of integers `< m` only.
>
> _Proof._ `r = m/p^e ≤ m/p`. By Bertrand there is a prime in `(r, 2r)`; every prime `> p` lies in `B_p`, and every
> prime `> p_w` is `W`-coprime and (being `> r ≥ r₁(p) > p`) not a multiple of `p`, so it lies in `B̃_p` too. Hence
> `r' < 2r ≤ 2m/p < m` for `p ≥ 3`. ∎ _Status: Bertrand + the argument of `Primegen.causality`; not separately
> formalised._

So Algorithm C is realisable as an online stream for the same reason as A and B: it never needs to know anything
about an integer it has not already scanned. The margin is wider than in B (`2m/p` rather than `m/2`).

### 2.5 Remark M-X: the obstruction is relocated, not removed

> **Remark M-X.** Deciding `r ∈ B_p` is deciding `gcd(r, P_{≤p}) = 1`, a function of `r mod P_{≤p}` alone.
> Tabulating it costs `Θ(P_{≤p}) = e^{(1+o(1))p}`; not tabulating it costs `Θ(π(p))` trial divisions. This is
> Conjecture X1 verbatim, with `P_{≤p}` in place of `P_{<p}`.

A tempting escape is _self-hosting_: by Claim M4 the multiplier `r'` needed by layer `(p,e)` at scan position `n` is
strictly less than `n`, and the generator has already computed `spf` of every candidate below `n` (§8). So layer
`(p,e)` could take `r'` from the generator's own output history, filtered by `spf(r') > p`. That works — and it costs
a stored history of length `n / p_{w+1}`, i.e. **an array proportional to the range**, which is precisely the thing
the architecture exists to avoid. The exact form therefore buys nothing over Algorithm A, and the interesting object
is the wheeled form.

## 3. Algorithm C∞ — the exact form, and why it is a normal form rather than an implementation

Realising Claim M1 exactly means streaming, for each `(p, e)` with `p^e ≤ N`, the set `p^e·B_p`, with `B_p` supplied
by the delegation of Claim M2. One-touch behaviour is immediate (each composite is produced by its own normal form,
once). But:

- By M2, producing `B_p` up to `X` requires every prime `q ∈ (p, X]` to be live, i.e. `π(X)` sub-streams; sharing
  across `p` helps (`B_{p'} ⊂ B_p` for `p' > p`) but the bookkeeping is exactly Algorithm A's tree with an extra
  index.
- By Remark M-X the alternative — a per-prime roughness oracle — is forbidden.

> **Claim M5.** Algorithm C∞ is Algorithm A read in the opposite orientation: A splits off the **largest** prime
> factor and indexes streams by the base `b = m/P(m)`; C∞ splits off the **smallest** prime factor **with its
> multiplicity** and indexes streams by `(p, e)`. Both are traversals of the same factorisation tree, both are
> one-touch, and neither is segment-restartable.
>
> _Status: informal identification; the exact live-stream count of C∞ is unmeasured (§11, item 3)._

C∞ is retained here as the mathematical statement (it is what makes §5 legible) and not as a proposal. Everything
below is the wheeled form, which is what "Algorithm C" means unqualified.

## 4. Design of the wheeled Algorithm C

Fix `w` and `W = p_1⋯p_w` exactly as in Algorithm B (`w = 6`, `W = 30030`, `κ_W = 0.1918` is the reference setting),
with the same `spokes` / `step` / `gte` tables (`paper.md` §4.2).

1. **Candidates** `n` run over `W`-coprime integers; the first `w` primes are emitted directly and their streams are
   structurally absent.
2. **For `p > p_w`** replace the exact cloud `B_p` by the tabulated relaxation

   ```
   B̃_p = {1} ∪ { r ≥ p : gcd(r, W) = 1, p ∤ r }  ⊇  B_p .
   ```

   Two constraints are kept exactly — `r ≥ p` (else the layer would claim numbers whose smallest factor is `r`, not
   `p`) and `p ∤ r` (else the layers of one prime would overlap each other, which is the naive reading of the
   original note and costs a factor of up to `log_p N` in duplicates on prime powers).

3. **The stream of layer `(p, e)`** is `p^e · B̃_p`, minus the single element `p` (the case `e = 1, r = 1`, which is
   prime, not composite). Its head is therefore

   ```
   head(p, e) = p^e            for e ≥ 2   (the spine element, r = 1)
   head(p, 1) = p · r₁(p)      where r₁(p) = least element of B̃_p greater than 1 .
   ```

   Since `r₁(p) > p`, every head is `≥ p²`, with equality exactly for `e = 2`.

4. **Advancement** is `r := next_adm(p, r)` — one wheel step plus a skip cursor for the multiples of `p` — then
   `v := pe · r`, where `pe = p^e` is carried in the record. No exponentiation, no division.

### 4.1 `next_adm`: `O(1)` amortised, one extra word

A record carries `mp`, a multiple of `p` with `mp ≥ r` (the _skip cursor_).

```
next_adm(p, r, mp):
    r := r + step[r mod W]
    loop:
        while mp < r: mp := mp + p
        if mp = r: r := r + step[r mod W]
        else: return (r, mp)
```

Cost: over a whole layer running to `X`, the wheel takes `≈ κ_W·X/p^e` steps while `mp` takes `≤ X/p^{e+1}`
increments; the ratio is `1/(κ_W·p) < 1` for every `p > p_w ≥ 13`. So the skip cursor adds strictly less than one
increment per advance, amortised — `O(1)` with a small constant, and branch-predictable (the skip is taken with
probability `≈ 1/p`).

### 4.2 Records

```
Rec = (p, pe, e, r, mp)        value = pe * r
```

`p`, `pe`, `r`, `mp` are machine words; `e ≤ log₂ N` fits in a byte. Five fields, four words. (Algorithm B's record
is `(p, a)`, two words.) `e` is carried only so that the generator can _report_ the valuation (§8); a
primes-only implementation drops it.

## 5. Specification

```
C():                                    # unbounded; no N anywhere
  emit p_1 … p_w
  primes := []            # primes > p_w, in order
  Q      := empty         # min-queue of Rec, keyed by value = pe*r
  act    := 0
  n      := p_{w+1}

  loop forever:
      # deferred activation: all layers of p become reachable exactly at n = p²
      while act < len(primes) and primes[act]^2 <= n:
          p := primes[act] ; act := act + 1
          (r1, mp1) := next_adm(p, p, p)                  # least admissible multiplier > p
          push (p*p,   p, p*p, 2, 1,  p  )                # spine head: the pure power p²
          push (p*r1,  p, p,   1, r1, mp1)                # layer-1 cloud head

      if Q empty or min_key(Q) > n:
          emit n ; primes.append(n)
      else:
          owner := ⊥
          while Q nonempty and min_key(Q) = n:            # drain: ≥1 claimant
              (v, p, pe, e, r, mp) := pop_min(Q)
              owner := min(owner, (p, e, r))              # by p; see Claim M11
              if r = 1:                                   # n = p^e : a pure power
                  push (pe*p, p, pe*p, e+1, 1, p)         # next spine element
                  (r1, mp1) := next_adm(p, p, p)
                  push (pe*r1, p, pe, e, r1, mp1)         # this layer's cloud head
              else:
                  (r, mp) := next_adm(p, r, mp)
                  push (pe*r, p, pe, e, r, mp)
          report(n, owner)                                # (spf, valuation, cofactor) — §8

      n := next_coprime(n)
```

Three points of design worth naming, because they are the only non-obvious parts:

- **A layer is created by the layer below it.** Popping a spine element `p^e` (the `r = 1` case) both extends the
  spine to `p^{e+1}` and opens the cloud of layer `e`. So the queue never holds a layer whose head has not been
  reached, and no global `N` is needed to decide how many layers `p` gets.
- **Activation fires at `n = p²` exactly**, as in Algorithm B: `p²` is `W`-coprime (since `p > p_w`), hence a
  candidate, hence scanned. Both pushed heads are `≥ p²`.
- **The drain is over all claimants**, as in Algorithm B. Unlike B, the minimum claimant carries its exponent, so the
  drain yields the normal form of `n` and not merely the fact that `n` is composite.

## 6. Correctness

> **Claim M6 (coverage).** Every `W`-coprime composite `m` is a value of layer `(p, e)` with `p = spf(m)`,
> `e = v_p(m)`.
>
> _Proof._ `p > p_w` since `m` is `W`-coprime; `r = m/p^e` satisfies `p ∤ r`, `gcd(r, W) = 1` (it divides `m`), and
> either `r = 1` or every prime factor of `r` exceeds `p`, whence `r > p`. So `r ∈ B̃_p`. Finally `m ≠ p` because
> `m` is composite, so `(e, r) ≠ (1, 1)`. ∎

> **Claim M7 (soundness).** Every key in `Q` is a `W`-coprime composite.
>
> _Proof._ A key is `p^e·r` with `p` prime `> p_w`, `r ∈ B̃_p`, `(e,r) ≠ (1,1)`. If `r = 1` then `e ≥ 2`; otherwise
> `r > p > 1`. Either way the key is a product of two integers `> 1`. `W`-coprimality is multiplicative. ∎

> **Claim M8 (no early claims).** Every key in `Q` is `≥ n`, and every key is `≥ p²` for its owning prime.
>
> _Proof._ Heads: `p²` is pushed exactly at `n = p²`, and `p·r₁(p) > p²`. Advancement strictly increases `r` hence
> the key; spine extension multiplies by `p`; a cloud opened at `n = p^e` starts at `p^e·r₁ > p^{e+1} > n`. ∎

> **Claim M9 (decision rule).** Under M6–M8, a `W`-coprime candidate `n` is prime iff no key in `Q` equals `n`; and
> `C()` emits exactly the primes, in increasing order, forever.
>
> _Proof._ By M8 the minimum key never precedes `n`. If `n` is composite, M6 puts it in a layer whose cursor has
> reached exactly `n` by monotonicity (its head was activated at `p² ≤ n`, and every intermediate layer element is
> itself a `W`-coprime candidate that was scanned). If `n` is prime, M7 forbids a key equal to `n`. ∎

_Status of M6–M9: proved here, not machine-checked. They are the exact analogues of `AlgB.coverage`,
`AlgB.not_prime_of_claims`, `AlgB.Inv.ahead` and `AlgB.emit_iff`; see §11._

## 7. Cost

### 7.1 Claimants and touches

> **Claim M10 (duplicate accounting).** For a `W`-coprime composite `m`, the set of layers that claim `m` is
>
> ```
> claimants_C(m) = { (p, v_p(m)) : p prime, p ∣ m, and ( m = p^{v_p(m)}  or  m / p^{v_p(m)} ≥ p ) } ,
> ```
>
> one layer per claiming prime. Moreover
>
> ```
> claimants_C(m) ⊆ claimants_B(m) = { p prime : p ∣ m, p² ≤ m } ,
> ```
>
> and both contain `spf(m)`.
>
> _Proof._ `(p,e)` claims `m` iff `p^e ∥ m` and `m/p^e ∈ B̃_p`, i.e. `m/p^e = 1` or `m/p^e ≥ p`; the exponent is
> forced to `v_p(m)` because `p ∤ r`. Inclusion: if `m/p^{v} ≥ p` with `v ≥ 1` then `m ≥ p^{v+1} ≥ p²`; if
> `m = p^{v}` with `m` composite then `v ≥ 2`. That `spf(m)` claims is Claim M6. ∎

The inclusion is strict in general. The smallest witness at `W = 30` is

```
m = 847 = 7 · 11²  :   B claims twice — (p=7, a=121) and (p=11, a=77)
                       C claims once  — layer (7,1) with r = 121
                       ( for 11: v_11 = 2, cofactor 7 < 11 and m ≠ 11², so no layer of 11 claims )
```

**How much does that save?** Per prime `p`, summing over layers,

```
#claims_C(p, N) = Σ_{e ≥ 1} ( [p^e ≤ N] + #{ r : p ≤ r ≤ N/p^e, gcd(r,W)=1, p ∤ r } )
                ≈ κ_W · N · (1 − 1/p) · Σ_{e ≥ 1} p^{-e}  =  κ_W · N / p ,
```

which is Algorithm B's `κ_W·N/p` to leading order — the layers merely partition the multiples of `p` that B handles
in one stream. The whole difference sits in the discarded tails `r < p`, one per layer instead of one per prime:

```
ops_B(N) − ops_C(N)  ≈  κ_W Σ_{p ≤ √N} p·( log_p N − 1 )  =  Θ( N^{2/3} / log N ) .
```

> **Cost statement.** `ops_C(N) = κ_W·N·( ln ln √N − ln ln p_w + o(1) ) − Θ(N^{2/3}/log N)`, plus `O(√N)` layer
> heads. At `N = 10¹²`, `w = 6`: `ops_B ≈ 0.46 N` and `ops_C` differs from it by `≈ 10⁻⁴ N`.
>
> _Status: measurement, as with every cost claim in this family. The `Θ(N^{2/3}/log N)` term is a heuristic count,
> not a theorem._

**So C is not a cheaper prime generator than B.** It is the same generator with a finer index, a strictly smaller
claimant set of the same average size, and a richer output. Anyone quoting C as "fewer touches" is quoting a
`10⁻⁴` effect.

### 7.2 Memory, uniform form

At scan `n` the queue holds, for each prime `p ≤ √n`: one spine record plus one cloud record per layer `e` with
`p^e ≤ n`. Hence

```
records_C(n) = Σ_{p ≤ √n} ( 1 + ⌊log_p n⌋ ) = 2·π(√n) + O(n^{1/3}) .
```

Twice Algorithm B's record count, at four words per record instead of two — a factor `≈ 4` in bytes. At
`N = 10¹²` that is `≈157 000` records against B's `78 498`.

### 7.3 Memory, thinned spine

The factor of two is removable, because the spine is nearly free:

- **`p²` is handled inline at activation.** The activation event for `p` fires exactly at `n = p²`, and it _knows_
  that `n` is composite with normal form `p²·1`. So it can report and mark `n` claimed without ever pushing a record
  for it. Only the layer-1 cloud is pushed.
- **Higher spine elements need a second activation cursor.** `p^e` with `e ≥ 3` requires `p ≤ n^{1/3}`, so maintain a
  cursor `act₃` over primes with `p³ ≤ n` (the same deferred-activation trick, one level up). It pushes the spine
  record `(p, p³, 3, 1, p)` and the layer-2 cloud head `p²·r₁(p)` (whose key `> p³ = n`, so M8 survives).

Then

```
records_C(n) = π(√n) + O( π(n^{1/3})·log n / log p )  =  (1 + o(1))·π(√n) ,
```

i.e. `≈ 78 500 + ≈ 5·10³` records at `N = 10¹²`. This is the recommended form; the uniform form of §5 is the one to
read, prove and test against.

### 7.4 Random-access restart

Preserved, layer by layer. For a segment beginning at `X` and a prime `p ≤ √X`:

```
for e = 1 .. ⌊log_p X⌋ :
    if p^e ≥ X and (e ≥ 2)   : r₀ := 1                             # the spine element itself
    else                     : r₀ := max( r₁(p), adm_ge(p, ⌈X/p^e⌉) )
    state(p,e) := ( p, p^e, e, r₀, p·⌈r₀/p⌉ )
```

where `adm_ge(p, y) = next_coprime_ge(y)` advanced past multiples of `p` — at most `⌈g_W/p⌉ + 1` wheel steps, where
`g_W` is the maximal `W`-coprime gap (`g_W = 34` at `W = 30030`), hence `O(1)`. Total restart cost is
`O(π(√X) + X^{1/3})` — the same as Algorithm B up to the layer factor. **Segments remain fully independent**, so
Algorithm C parallelises exactly like B and unlike A.

### 7.5 Vectorisation

The advance `r += step[r % W]; v = pe*r` vectorises as in `paper.md` §5.3. The skip cursor introduces a
data-dependent branch with probability `1/p ≤ 1/17`; the branchless form is
`taken := (mp == r); r += taken * step[r % W]; mp += (mp <= r) * p`, which is measurably worse below `p ≈ 50` and
better above it. Measure before choosing.

## 8. What Algorithm C emits that A and B do not

Every drained candidate yields its **min-factor normal form**:

> **Claim M11 (streaming min-factor oracle).** When the drain at candidate `n` pops the claimant with the smallest
> `p`, that record's `(p, e, r)` satisfies `p = spf(n)`, `e = v_p(n)`, `r = n/p^e`.
>
> _Proof._ Every claimant's `p` divides `n`, so every claimant is `≥ spf(n)`; and `spf(n)` claims (Claim M6). The
> exponent is exact because `p ∤ r` (Claim M10). ∎

So the output of `C()` is not a bit-stream of primality but the sequence

```
n  ↦  ( spf(n), v_{spf}(n), n / spf(n)^{v} )     for every W-coprime n, with primes the fixed points (r = 1, e = 1)
```

at no extra cost beyond the drain that was happening anyway. Direct consumers:

- **factor tables / smallest-prime-factor tables** without a range array (the cofactor `r` is the next input, and
  `r < n` by Claim M4, so a bounded window suffices if the consumer runs a second pass);
- **`ω`, `Ω`, `μ`, `λ`, radical, squarefree tests** — all are functions of the successive normal forms;
- **smooth / rough number enumeration**: layer `(p,e)` _is_ the set of numbers with `spf = p` and `v_p = e`, so
  `y`-smooth and `y`-rough streams are unions of layers, selected by index rather than filtered by test;
- **prime-power enumeration** for free: the spine records are exactly the prime powers `p^e`, `e ≥ 2`, in order.

Algorithm B can produce `spf` (its minimum claimant is also `spf`, since `spf(m)² ≤ m` always) but not the
valuation, and not the cofactor without a division. Algorithm A produces `m = b·P(m)`, i.e. the _largest_ prime
factor, which is the harder end to iterate on.

This — not touch count — is the case for Algorithm C.

## 9. The lattice reading

`paper.md` §2.5 / `fractal.md` read the construction as a Moran/IFS recursion
`S_{k+1} = (p tilings of S_k) \ p·S_k`, whose deleted set is the stream `Θ_p = p·A_p`. Claim M1 refines the deleted
set:

> **Claim F4 (graph-directed form).** With `p = p_{k+1}`:
>
> 1. the deleted copy `p·A_p` is itself an infinite disjoint tower `⨄_{e≥1} p^e·B_p` of affine copies of one set
>    `B_p`, at ratios `p^{-1}, p^{-2}, p^{-3}, …`;
> 2. `B_p = {1} ⊎ ⨄_{q>p} q·B_q` (Claim M2), so the system is **graph-directed** with node set the primes and an
>    edge `p → q` for every `q > p`;
> 3. hence the whole object is generated by one grammar: nodes = primes, edges = "next prime factor", loops =
>    "same prime again", and Algorithm C is the priority traversal of that grammar with loops run-length encoded.
>
> _Status: routine (unique factorisation); not formalised._
>
> **Caution.** Do **not** read a dimension off this. The naive Moran equation `Σ_{q>p} q^{-s} = 1` has a root `s > 1`,
> which is nonsense as a dimension; the reason is that the pieces here are arithmetic progressions inside a residue
> lattice, not nested intervals with disjoint convex hulls. Claim F2 (`box dimension = 1`, measure `0`) stands and is
> computed the right way, from `φ(P_k)` and `P_k` directly.

The one genuinely new statement is (1): the single Moran copy deleted at each stage is _internally_ geometric, with
the exponent spine as its scaling direction. That is the lattice-side image of "layers", and it is why the layer
index costs nothing structurally — it was already there.
