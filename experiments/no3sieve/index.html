Not a bug: collinearity has no distance cutoff. At the default horizon W = ∞ the four 2-wide empty strips through the origin are forced. The greedy takes (0,0),(0,1),(1,1),(1,0), which puts two points on each of y=0, y=1, x=0, x=1 (and on y=x, x+y=1). A line holding two points is dead at every distance — collinearity is integral, not metric — so each vacancy has an explicit certificate: (t,0) is collinear with (0,0),(1,0) for all t, (0,t) with (0,0),(0,1), and so on. Hover any strip cell to see its pair and its I2 load.

If you want the constraint bounded, set W in the Engine panel: triples of L∞ span > W are then permitted, the strips refill beyond W, and the set acquires positive density (theory.md §2A). W is not an approximation — P_W equals P_∞ cell-for-cell inside B(⌊W/2⌋) (T2A.7), and every s×s window with s ≤ W+1 is fully, classically valid (C2A.3). Enable paranoid to assert the sieve neither over- nor under-blocks at whatever W you pick (I4, both directions).
